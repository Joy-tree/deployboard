Deploy flow

From push to live in three steps.

No YAML. No complex configuration. Just GitHub, a build command, and a subdomain.

01
Connect your repository
Paste your GitHub repo URL and optionally a Personal Access Token for private repos. Choose the branch to deploy.
02
Configure your build
Set your install and build commands (defaults to npm install + npm run build), output directory, Node.js version, and env vars.
03
Deploy and go live
Hit Deploy. Watch the real-time logs stream. Your site goes live at your-subdomain.yourdomain.com in seconds.

Deploying a Site
1. Create a New Deployment
Click + New Deployment in the sidebar. Enter your project name, GitHub repo URL, and choose a subdomain.
2. Configure Build Settings
Set your install command (e.g. npm install), build command, and output directory. For plain HTML sites use echo skip for both and . as output.
3. Watch Live Logs
The terminal streams build output in real time. Build steps are shown in the collapsible panel below the terminal.
4. Your Site Goes Live
On success, your site is immediately accessible at subdomain.joytree.site

Troubleshooting
Build fails at install step — Check that your repo has a valid package.json. Try npm install as install command.
Build succeeds but site shows 404 — Your output directory is wrong. Check the table above for your framework's correct output folder.
Site shows "not deployed yet" — The build succeeded but the subdomain hasn't been visited yet. Wait 30 seconds and try again.
Screenshot not loading — Screenshots take 10–15 seconds to generate. If still missing after a redeploy, the screenshot service may be temporarily unavailable.
Status stuck on building — Refresh the page. If it persists, the build timed out — check the logs and redeploy.
